# Retrieva ユーザーガイド

Retrievaは、カードと復習履歴をVault内のMarkdownファイルに保存する、Obsidian向けの間隔反復プラグインです。復習間隔の計算にはFSRSを使用します。外部データベース、アカウント、ネットワーク接続は必要ありません。

## 動作要件とインストール

- Obsidian 1.13.0以降
- デスクトップ版・モバイル版の両方に対応

Community pluginsに掲載された後は、Obsidianの **設定 → コミュニティプラグイン → 閲覧** で「Retrieva」を検索し、インストールして有効化します。

手動で導入する場合は、同じバージョンのGitHub Releaseから `main.js`、`manifest.json`、`styles.css` をダウンロードし、次のフォルダへ置きます。

```text
<Vault>/.obsidian/plugins/retrieva/
```

Obsidianを再読み込みし、**設定 → コミュニティプラグイン** でRetrievaを有効にしてください。

## 最初のカードを作る

### 1. 元になるノートを書く

通常のノートに、問題と答えを見出しやブロックID付きで記述します。元ノートにRetrieva固有の記法は必要ありません。

```markdown
# 問題

間隔反復とは何ですか？

# 答え

忘れそうな時期に合わせて復習を行う学習方法です。
```

### 2. カードを作成する

コマンドパレットから **Retrieva: カードを作成** を実行し、次を入力します。

- **表面の埋め込み**: `![[学習ノート#問題]]`
- **裏面の埋め込み**: `![[学習ノート#答え]]`
- **ファイル名**: カードファイルの名前
- **プリセット**: 通常は `default`

アクティブなノートからコマンドを実行すると、そのノートの `#Front` と `#Back` を参照する埋め込みが初期値になります。必要に応じて書き換えてください。

Retrievaは **カードの既定フォルダ** に1枚のMarkdownファイルを作り、作成したカードを開きます。同名ファイルがすでにある場合は上書きしません。

同じ内容を両方向から覚えたい場合は、**Retrieva: 表裏カードを作成** を使います。表と裏を入れ替えた2ファイルが作られ、同じ兄弟グループに設定されます。

### 3. デッキ用タグを付ける

作成直後のカードには `retrieva-card` タグが自動で付きます。復習範囲を選べるよう、カードのfrontmatterへ任意のタグを追加します。

```yaml
tags:
  - retrieva-card
  - biology
  - exam/biology
```

`retrieva-card` はカード識別用です。`biology` や `exam/biology` がデッキ選択に使うタグです。カードはVault内のどのディレクトリに置いても認識され、既定の `Cards` ディレクトリに限定されません。

## 復習する

### 復習範囲を選ぶ

リボンの脳アイコン、またはコマンドパレットの **Retrieva: 復習範囲を選択** を開きます。

「Retrievaカードで使用中のタグ」には、現在有効なカードで使用されているタグと件数が表示されます。タグを選んで **開始** を押してください。入力欄へタグを直接入力することもできます。

親タグを選ぶと、その下のネストしたタグも対象になります。たとえば `exam` を選ぶと、`exam/biology` と `exam/history` のカードも含まれます。

件数は **今すぐ復習できる枚数 / 選択範囲内の有効な総カード数** です。総数には未来に予定されたカードも含まれますが、保留中のカードと当日除外された兄弟カードは復習キューに入りません。

「名前を付けて保存」を有効にすると、そのタグ範囲を次回からワンタップで開けます。保存済み範囲は設定画面でも編集・削除できます。

### カードに回答する

1. 表面を確認します。
2. カード部分をタップまたはクリックして答えを表示します。
3. 画面下部の評価を選びます。

評価は次の4段階です。各ボタンには、その評価を選んだ場合の次回予定も表示されます。

| 評価     | 目安                           |
| -------- | ------------------------------ |
| もう一度 | 思い出せなかった               |
| 難しい   | 思い出せたが、かなり難しかった |
| 普通     | 正しく思い出せた               |
| 簡単     | 迷わず思い出せた               |

評価すると復習イベントがカードファイルへ追記され、次のカードへ進みます。

### スキップ・保留・Undoの違い

- **スキップ**: そのカードを現在のセッションの残りから一時的に外します。履歴は書き込みません。ほかのカードを終えると、スキップしたカードを再試行するか「今日は終了」を選べます。
- **保留**: 今後の復習キューから継続的に外します。保留イベントが履歴へ追記されます。
- **直前の復習を取り消す**: このセッションで最後に行った評価を取り消します。評価後にカードファイルが変更された場合や、取り消し済みの場合は実行できません。

カードの内容を確認・編集したい場合は、ツールバーの **カードファイルを開く** を使います。保留カードは **保留一覧** からファイルを開くか、復習へ戻せます。

## カードの保存形式

1枚のカードは1つのMarkdownファイルです。Retrievaが管理する完全なカードは、おおむね次の構造になります。

```markdown
---
retrieva-preset: default
tags:
  - retrieva-card
  - biology
---

![[学習ノート#問題]]

<!--RETRIEVA-ANSWER-->

![[学習ノート#答え]]

<!--RETRIEVA-CARD {"v":1,"id":"..."}-->

<!--RETRIEVA-LOG
{"v":1,"eid":"...","type":"created","parent":null,"at":"...","zone":"...","state":{...}}
RETRIEVA-LOG-->
```

編集できる部分は次のとおりです。

- frontmatterのデッキ用タグ
- `retrieva-preset`
- `RETRIEVA-ANSWER` より前の表面
- `RETRIEVA-ANSWER` より後、`RETRIEVA-CARD` より前の裏面

次の部分はRetrievaが管理するため、通常は編集しないでください。

- `retrieva-sibling-group`
- `RETRIEVA-CARD` のカードID
- `RETRIEVA-LOG` 内のJSONL履歴

各マーカーはカード内に正確に1個必要です。カードの本文やコード例に同じマーカー文字列を記述すると、破損カードとして検出されることがあります。

### 手動またはLLMでカードを作る

カードはプラグインの作成画面を使わず、次の最小形式で作ることもできます。

```markdown
---
retrieva-preset: default
tags:
  - retrieva-card
  - topic/example
---

![[Source note#Question]]

<!--RETRIEVA-ANSWER-->

![[Source note#Answer]]
```

Retrievaがこのファイルを最初に索引したとき、UUIDv7のカードIDと `created` イベントを自動生成します。手動またはLLMでID、ログ、兄弟グループを作らないでください。表裏ペアにはプラグインの **表裏カードを作成** を使ってください。

## プリセット

初回利用時に `Retrieva/Presets/default.md` が自動作成されます。プリセットはカードとは別のMarkdownファイルです。

```markdown
---
retrieva-preset-definition: true
retrieva-preset-id: default
scheduler: fsrs
desired-retention: 0.9
maximum-interval-days: 36500
learning-steps:
  - 1m
  - 10m
relearning-steps:
  - 10m
exclude-new-siblings-today: true
exclude-review-siblings-today: true
---

# Default SRS preset
```

| 項目                            | 意味                                            |
| ------------------------------- | ----------------------------------------------- |
| `retrieva-preset-id`            | カードの `retrieva-preset` から参照する一意のID |
| `scheduler`                     | 現在は `fsrs` のみ                              |
| `desired-retention`             | 目標保持率。0.7〜0.99                           |
| `maximum-interval-days`         | 復習間隔の上限日数。1以上の整数                 |
| `learning-steps`                | 新規学習中の短期ステップ。例: `1m`, `10m`       |
| `relearning-steps`              | 忘却後の再学習ステップ                          |
| `exclude-new-siblings-today`    | 新規の兄弟カードを同日に続けて出さない          |
| `exclude-review-siblings-today` | 復習済みの兄弟カードを同日に続けて出さない      |

プリセットIDはVault内で重複できません。設定画面の **プリセットファイル** から、認識済みのプリセットを開けます。

現在、設定画面の兄弟除外トグルは、各プリセットに書かれた同名項目より優先して全プリセットへ適用されます。

## 設定

**設定 → Retrieva** で次を変更できます。

| 設定                       | 内容                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| カードの既定フォルダ       | Retrievaの作成コマンドが新規カードを保存するVault相対パス。既存カードの認識範囲は制限しません |
| 除外ディレクトリ           | 索引しないVault相対ディレクトリ。1行に1件                                                     |
| リボンアイコンを表示       | 復習範囲を開くショートカットの表示                                                            |
| 新規の兄弟カードを当日除外 | 新規カードを評価した日に、同じ兄弟グループの別カードを除外                                    |
| 復習の兄弟カードを当日除外 | 復習カードを評価した日に、同じ兄弟グループの別カードを除外                                    |
| 保存済みの範囲             | 名前付きのタグ範囲を追加・編集・削除                                                          |
| LLMプロジェクトskill       | Codex・Claude Code向けのRetrieva記法をVaultへ設定                                             |

除外ディレクトリ内では、カード、プリセット、破損したマーカー候補を検出・初期化・修復しません。大きなアーカイブ、テンプレート、バックアップなどを対象外にすると、誤検出や不要な読み込みを避けられます。設定欄からフォーカスを外すとインデックスが再構築されます。

## コマンド一覧

| コマンド                               | 動作                                                   |
| -------------------------------------- | ------------------------------------------------------ |
| 復習範囲を選択                         | タグを選び、復習を開始                                 |
| カードを作成                           | 表面・裏面を指定して1枚作成                            |
| 表裏カードを作成                       | 両方向の兄弟カードを2枚作成                            |
| カードインデックスを再構築             | Vault内の対象Markdownを再読込                          |
| Vault内のカードを検証                  | カードとプリセットを検査し、破損復元ビューを開く       |
| 現在のカードをリセット                 | アクティブなカードの学習状態を新規へ戻すイベントを追記 |
| 現在のカードを保留または再開           | アクティブなカードの保留状態を切り替え                 |
| 保留中のカードを開く                   | 保留一覧を表示                                         |
| Codex・Claudeのプロジェクトskillを設定 | LLM向けskillをインストールまたは更新                   |

「現在のカード」を対象にするコマンドは、アクティブなMarkdownファイルが有効なRetrievaカードの場合だけ利用できます。リセットは過去の履歴を削除せず、リセットイベントを追記します。

## 検証と破損復元

**Retrieva: Vault内のカードを検証** は、主に次の問題を検出します。

- 必須マーカーの欠落・重複・順序違反
- frontmatterやイベントJSONの構文エラー
- カードIDまたはイベントIDの重複
- `created` イベントの欠落
- イベントの `parent` がつながらない履歴や分岐
- 存在しない、無効、または重複したプリセット
- `retrieva-card` タグのないマーカー付きファイル

破損復元ビューでは、対象ファイルを開くほか、状況に応じて次の操作ができます。

- 欠落したカードIDと `created` イベントを生成
- 重複したカードIDを再発行
- イベントを時刻順に並べ、`parent` を再生成
- JSONLを検証して保存

履歴編集欄は1行につき1つのJSONオブジェクトです。不要な分岐イベントの選択は自動化されないため、どの履歴を残すか判断してから削除してください。修復前にはVaultのバックアップまたはバージョン管理を推奨します。

マーカー自体が壊れている場合は、先にカードファイルを直接開いてマーカーを直す必要があります。プリセットの問題はプリセットファイルのfrontmatterを修正し、インデックスを再構築してください。

## Codex・Claude Codeとの連携

設定画面の **LLMプロジェクトskill → 設定・更新**、または同名のコマンドを実行すると、次のファイルをVaultへ書き込みます。

```text
.agents/skills/retrieva/SKILL.md
.claude/skills/retrieva/SKILL.md
```

既存ファイルと同じ内容なら変更しません。内容が異なる場合は、ファイル全体を置き換える前に確認ダイアログを表示します。

このskillはLLMに、Vaultの既存ルールとカード配置に従うこと、配置先が不明ならユーザーへ確認すること、レビュー履歴を保持すること、機械管理IDを生成しないことを指示します。

## データ、プライバシー、性能

Retrievaはカードを任意のディレクトリへ配置できるようにするため、Retrievaの画面またはカード関連コマンドを初めて開いた時点で、Vault内のMarkdownファイルを列挙して内容を読みます。プラグイン有効化直後には索引を開始しません。

- カード索引ではMarkdown以外のファイルを列挙しません。
- 設定した除外ディレクトリ以下は読みません。
- ファイル変更は監視され、索引へ反映されます。
- データは現在のVaultとObsidianのプラグイン設定内だけに保存されます。
- ネットワーク通信、テレメトリ、広告、外部サービスはありません。

大規模Vaultで初回表示が遅い場合は、カードを置かない大きなディレクトリを **除外ディレクトリ** に追加してください。

## よくある質問

### カードは `Cards/` 以外でも認識されますか？

はい。Vault内の任意の場所に置けます。`retrieva-card` タグ、有効な `retrieva-preset`、正しいカード構造が必要です。除外ディレクトリ内は認識されません。

### 元ノートを移動・改名できますか？

Obsidianのリンク自動更新を有効にしていれば、通常の埋め込みと同様に追従します。移動後はカードを開き、埋め込みが正しく表示されることを確認してください。

### カードの問題文や答えはどこを直しますか？

埋め込みを使っている場合は元ノートを編集するのが安全です。カードファイル内の表面・裏面も編集できますが、機械管理マーカーとログは変更しないでください。

### スキップすると次回予定は変わりますか？

いいえ。スキップは現在のセッションだけの操作で、イベントを記録せず、FSRSの状態も変えません。

### 保留を何度も切り替えるとログが増えるのは正常ですか？

はい。保留と再開は状態変更の履歴として、その都度イベントを1行追記します。現在状態だけでなく変更履歴もMarkdownから復元できる設計です。一時的に後回しにするだけならスキップを使ってください。

### プラグイン設定を削除すると復習履歴も消えますか？

消えません。復習履歴は各カードのMarkdown内にあります。保存済み範囲や既定フォルダなどのUI設定は失われます。

### 表示言語はどう決まりますか？

Obsidianのロケールが日本語なら日本語、それ以外は英語を使用します。未定義の翻訳は英語へフォールバックします。

## 安全な運用の要点

1. 知識本文は通常ノートに置き、カードから埋め込む。
2. カードには `retrieva-card` とデッキ用タグを付ける。
3. `RETRIEVA-CARD` と `RETRIEVA-LOG` は編集しない。
4. 一時的な後回しにはスキップ、長期除外には保留を使う。
5. 手動修復の前にVaultをバックアップする。
